zinc.css

A classless stylesheet for reports, dashboards and forms. You write plain semantic HTML with no class names, and zinc sets it as one calm column, with colour kept for what you focus, check or choose.

Why classless

A page should be quick to write and easy to read. A classless stylesheet helps with both.

  • Nothing to look up. If you know HTML, you know zinc. There are no class names to remember, misspell or invent.
  • One shape, learned once. A page opens with the answer and is built from short, labelled sections, so a reader knows where to look on every page.
  • One file, no build. A single <link> from a CDN. The page is one self-contained HTML file to open, save or send.
  • Colour means state. Links and buttons are ink. The accent marks only focus, checked controls, chosen options and progress, so the answers in a form stand out.

Getting started

Add one <link> to the <head> of a page.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Hello</title>
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/zinc.css@0.0.0-pre.7/zinc.min.css" />
</head>
<body>
  <main>
    <h1>Hello, world</h1>
    <p>No classes. <a href="https://example.com">Just markup.</a></p>
    <button>It styles itself</button>
  </main>
</body>
</html>

Keep the viewport <meta>: without it, phones render the page at desktop width. Pinning the exact version, as above, means the page can't change under you; an unpinned URL, zinc.css/zinc.min.css, follows the newest release. unpkg serves the same files, and each package has zinc.css and the minified zinc.min.css.

From npm, run npm install zinc.css, then link node_modules/zinc.css/zinc.css or import "zinc.css" with a bundler that handles CSS.

Every element zinc styles, from inline text to each input type, is on the elements page.

Examples

Each example is a whole page of one common kind. The content is invented, so read it for its shape, not its subject. Open one to see it whole; there, the Theme button at the top right shows it in dark mode, with another accent or on the beige paper.

  • Audit decisions A rich feedback form, for reviewing a long list item by item.
  • Questions A questionnaire for the choices only you can make.
  • Inbox briefing A digest of anything that arrives as a stream: mail, alerts, tickets.
  • Code health A health check of one thing: a codebase, a budget, a project.
  • Recommendations A ranked list of findings, the few that matter first.

With an agent

zinc also suits the pages a coding agent writes when a chat reply would run long. The examples above are those pages: a digest, a health check, ranked findings, a questionnaire, and a review form with a row of choices for each item. Each layout is checked on a phone and on a wide screen, in light and dark, so the agent has a worked pattern to copy.

An agent skill, html-zinc, goes with it. It tells your agent when a page beats a chat reply, how to shape the page so it reads well, and how to ask you several questions at once with a form you fill in and paste back. Paste this into your agent:

Install the html-zinc skill from the zinc.css repo:

npx skills add Rkaede/zinc.css --skill html-zinc

From now on, when I ask for a report, a comparison, a dashboard or anything
that reads better as a page than as a chat reply, use the skill to write it
as a single HTML file styled with zinc.css, and open it for me. When you need
several decisions from me at once, use its questions mode: a form I fill in
in the browser and paste back to you.

The skills command installs the skill for Claude Code, Codex and most other coding agents.

A side note on tokens: any classless stylesheet, zinc or another, saves an agent output tokens, because the agent writes markup and no CSS or utility classes.
