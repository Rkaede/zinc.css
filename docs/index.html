Classless CSS for AI agents · 0.1.0-next.0

zinc.css

A stylesheet for the pages AI agents write: reports, dashboards, and forms that ask you questions. The agent writes plain semantic HTML with no class names, and zinc sets it as one calm column, with labels in the margin and colour kept for what you focus, check or choose.

Why classless

When an agent answers with a page instead of a long chat reply, that page should be easy for the agent to write and easy for you to read. A classless stylesheet helps with both.

  • Nothing to look up. The agent already knows HTML. There are no class names to remember, misspell or invent, and no strings of utilities to spend tokens on.
  • One shape, learned once. A page opens with the answer and is built from short, labelled sections, so you know where to look whichever agent wrote it.
  • One file, no build. A single <link> from a CDN. The page is one self-contained HTML file to open, save or send.
  • Colour means state. Links and buttons are ink. The accent marks only focus, checked controls, chosen options and progress, so the answers in a form stand out.

Getting started

zinc comes with an agent skill, html-zinc. It tells your agent when a page beats a chat reply, how to shape the page so it reads well, and how to ask you several questions at once with a form you fill in and paste back. Paste this into your agent:

Install the html-zinc skill from the zinc.css repo:

npx skills add Rkaede/zinc.css --skill html-zinc

From now on, when I ask for a report, a comparison, a dashboard or anything
that reads better as a page than as a chat reply, use the skill to write it
as a single HTML file styled with zinc.css, and open it for me. When you need
several decisions from me at once, use its questions mode: a form I fill in
in the browser and paste back to you.

The skills command installs the skill for Claude Code, Codex and most other coding agents. The pages it writes look like the examples below.

Examples

Whole pages of the kinds agents write, each showing a few of zinc's patterns, with the markup that makes each one in brackets. The people, companies and projects in them are invented. Use the Theme button at the top right to see them in dark mode, with another accent or on the beige paper.

  • Inbox briefing

    A morning summary of an inbox: what needs a reply, receipts, and what was filed.

    Section labels in the margin (a <section> that opens with an <h2>). Entry lists of messages (<ul role="list">). Long tables folded away, with a summary that counts the rows (<details>).

  • Code health

    A dashboard for one codebase: what to fix first, then the evidence by area.

    Key figures (a <dl> of <div> pairs). Fact sheets (a plain <dl>). A note (<aside>). Folded tables. A closing Method section.

  • Recommendations

    A long report of 27 suggestions, the first five up front.

    A lede that gives the answer (the first <p> after the <h1>). A folded index, and a disclosure for each sketch (<details>). Tables and a note.

  • Feature triage

    Nine feature ideas to decide on, with a searchable audit of the research behind them.

    A toolbar of filters (<menu>). A decision per idea (a segmented role="radiogroup"). One card for the lead idea (<article>). Key figures and notes.

  • Questions

    The decisions an agent needs before cleaning up a shared drive, answered in the browser.

    A numbered questionnaire (<form data-form="questions">, one <fieldset> per question). Choice cards (a <label> around an input and a <span>). Switches (role="switch"). An action bar that sticks to the bottom (a <footer> with an <output>).

  • Every control

    A short setup form that uses each kind of input once.

    A question form with choice cards, switches, text, email, URL, number, date, time and range fields, and a required mark (<abbr title="required">).

  • Audit decisions

    A long form: discuss, defer or skip each finding of a code audit.

    A segmented decision on every entry (a role="radiogroup" inside role="list"). A filter toolbar (<menu>). A contents list with a label of its own (a <nav> that opens with an <h2>).

Install by hand

The skill links zinc for you. To use it in a page of your own, add one <link> to the <head>.

Use the next tag. These docs cover 0.1.0-next.0, a pre-release published under the npm next tag. An unpinned URL or a plain npm install zinc.css gets latest, which is still an older version with a different look.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Hello</title>
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/zinc.css@0.1.0-next.0/zinc.min.css" />
</head>
<body>
  <main>
    <h1>Hello, world</h1>
    <p>No classes. <a href="https://example.com">Just markup.</a></p>
    <button>It styles itself</button>
  </main>
</body>
</html>

Keep the viewport <meta>: without it, phones render the page at desktop width. Pinning the exact version, as above, means the page can't change under you; zinc.css@next follows the newest pre-release. unpkg serves the same files, and each package has zinc.css and the minified zinc.min.css.

From npm, run npm install zinc.css@next, then link node_modules/zinc.css/zinc.css or import "zinc.css" with a bundler that handles CSS.

Every element zinc styles, from inline text to each input type, is on the elements page.

Theming

Three attributes on <html> set the theme. Try them with the Theme button at the top right.

data-mode
light or dark. Leave it off to follow the system setting.
data-accent
electric (the default, a dusty blue), forest or violet.
data-paper
beige swaps the white page for a pale green-beige paper. Works on <body> too.

Every colour, size and font is a custom property you can override on :root. The README lists them all. zinc sits in a cascade layer, zinc, so your own CSS wins over it wherever it loads and whatever its specificity.

Browsers

zinc is written for current browsers and ships no fallbacks. It relies on :has(), light-dark(), color-mix() and cascade layers, which need Chrome and Edge 123, Firefox 121 or Safari 17.5 and later. In somewhat older browsers, back to early 2022, the page still reads, but accent colours, section labels, key figures and choice cards fall back to plain styles. Browsers from before 2022 don't support cascade layers, so they skip zinc entirely and show their default styles.
