Text

Inline text

Links are ink with a hairline underline, and turn to the accent on hover (with a mouse). <mark> and <ins> take a light tint of the accent; deleted text is muted.

Addresses and rules

An <address> is muted and upright. An <hr> is a hairline with generous space around it.

Headings

<h1> takes the title size, which grows with the window from 1.75rem to 2.25rem. <h2> is 1.375rem, <h3> is body size, <h4> and <h5> are small, and <h6> is 0.875rem; <h5> and <h6> are muted. All headings are weight 600 and balance their lines. A heading that opens a header, section, article, aside, details, dialog, list item, fieldset, form or table cell loses its top margin.

Lists

Markers are muted, and numbers use tabular figures so they line up. In a section on a screen 48rem or wider, a list loses its indent and its markers hang in the margin, as the list below this paragraph does.

  • Bullets and numbers sit outside the text edge.
  • The words stay on the edge.

A list with role="list" is a list of entries with no markers; a <dl> is a fact sheet or a row of key figures; a <menu> is a toolbar. The examples show each of them in a whole page.

Quotes

A blockquote has a quote bar on its leading edge, which hangs in the margin in a section on a wide screen. A <cite> inside it becomes a small attribution line with a dash in front.

Code

Inline

Inline <code> sits on a faint tint, <kbd> looks like a key, and <samp> is monospace with no fill. A long path in inline code breaks rather than running out of its line.

Blocks

A <pre> is a tinted panel that reaches past the text edge on both sides, so the code inside stays on the edge. It scrolls sideways rather than wrap, and tabs are two spaces wide.

Media

Images, video, SVG and canvas never grow wider than their container. Images and video are blocks with rounded corners. An inline <svg> fills with the text colour. A <figcaption> is small and muted.

Tables

A table runs the full width of the column with no left padding on the first column and no right padding on the last, so its rules start and end on the text edges. Header cells are small and muted over a firm rule, numbers use tabular figures, the caption sits underneath, and a footer row is bold over a firm rule. On a phone, cells may break inside a word so a table of paths still fits.

Fold a long table into a <details>, and say in the <summary> what is inside and how many rows, as the inbox briefing does.

Details

A <summary> is a line of text with a chevron and no box. The chevron turns when it opens, and the content grows and fades in where the browser supports it. In a section on a wide screen the chevron hangs in the margin. Consecutive details sit close together.

Dialog

A <dialog> is the one thing that floats, so it is the one thing with a shadow. It centres itself, stays inside the window, fades and scales in, and dims the page behind it. A <form> inside a dialog lays its contents out in a wrapping row, which suits a row of buttons. With method="dialog", a button closes it with no script.

The demo opens the dialog with an invoker command (commandfor and command="show-modal"). In a browser without invoker commands, call showModal() from a script.

Forms

A <label> is a small, medium-weight line above its field. Fields take the full width, with a firm outline that has at least 3:1 contrast against the page. A focused text field swaps the outline for an accent edge and a soft halo; other controls get the standard accent focus ring. A label after a field keeps its distance from it.

Text fields

Other field types

Every text-like input type gets the same field: url, tel, number, date, time, datetime-local, month, week, and an <input> with no type.

Textarea and select

A textarea starts 6.5rem tall and resizes vertically. A select gets a drawn chevron; a multiple select drops it.

Checkboxes and radios

A label that wraps a checkbox or radio becomes a line of body text with the control in front. Checked, the control fills with the accent. A <fieldset> is an unboxed group headed by its <legend>.

Add a <span> inside the label and the same controls become choice cards; add role="switch" to a checkbox for a switch. The questions example uses both.

Range

A thin track in the control-outline colour, with an accent thumb.

Colour and file

A colour input is a small swatch with a field outline. A file input's button is a soft tinted button, with the file name muted beside it.

Validation

A field turns its outline to the danger colour when it is invalid, but only after the person has changed it or tried to submit (:user-invalid), so an empty form never starts out red. Type a number outside the range below and leave the field.

Disabled

Disabled controls fade to 55% and lose the pointer cursor. Disabling a <fieldset> dims its controls but not its legend.

Buttons

A button is ink, not accent: it is a command, and its shape says so. A row of buttons sits well in a <menu>, which wraps them with a gap (the feature triage has a toolbar of filters). On a touch screen every button is at least 2.75rem tall (2.25rem for a small one).

Variants

Set data-variant to secondary, outline, ghost or danger. Use one primary button per group.

Sizes

Input buttons and reset

Submit and button inputs look like buttons. A reset button or input is secondary unless you give it a variant.

Links as buttons

A link with role="button" takes the button styles, and so does any element with a data-variant. A link has no disabled state, so use aria-disabled="true", which fades it and stops clicks.

Disabled

Button groups

Wrap buttons in an element with role="group" to join them into one segmented strip, with a hairline of page between the parts. For a choice of one option among a few, use a segmented control instead: radios inside an element with role="radiogroup", as in the feature triage.

Navigation

A <ul> inside a <nav> is a wrapping row of small, muted links with no underline. The link with aria-current turns to the text colour and keeps an underline, so colour is not its only cue. A link-button inside keeps the button styles.

Put a nav alone in the body's <header> for a top bar, as on this site.

Progress

<progress> and <meter> are thin, rounded bars filled with the accent. A meter stays the accent whatever its low, high and optimum say: the accent marks the amount, not a judgement of it.
