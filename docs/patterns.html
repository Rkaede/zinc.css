Patterns

A few arrangements of ordinary elements get a layout of their own. Each is still plain HTML: the structure, an ARIA role or a data- attribute is the hook.

Margin labels

Build the page from <section> elements inside <main>, each opening with an <h2>. From 56rem wide, the page gains a left margin and each <h2> moves into it as a small label that stays in view while its section scrolls past. The title and every line of content keep one edge to the right of it. Below 56rem the labels are ordinary headings.

<main>
  <section>
    <h2>Do next</h2>
    <p>Two modules need attention this week…</p>
  </section>
  <section>
    <h2>Findings</h2>
    …
  </section>
</main>

Use it for any page longer than a screen: reports, docs, dashboards. Keep labels to one to three words and put the sentence under them. This page is built this way; on a wide window the labels are on the left. See it on its own in the page structure demo, and read the rules in Getting started.

Header and lede

In the page header (body > header or main > header), a <p> before the <h1> is a small, muted line of context: where this came from, when, for whom. The first <p> after the <h1> is the lede, a size up and in full text colour. Any later paragraphs in the header are muted.

<header>
  <p>Harbor API · Run 412 · 3 March</p>
  <h1>Code health</h1>
  <p>Two modules need attention this week; the rest is steady.</p>
</header>

Use it to answer the page's question before the reader scrolls: the lede is the one thing every reader should take away. The header of this page uses it, and so does the page structure demo.

Key figures

A <dl> whose <dt>/<dd> pairs are each wrapped in a <div> is a row of headline numbers. The value leads in large type and the label sits under it, though the label comes first in the markup, so it is read first. The row wraps to fit.

Use it at the top of a report or dashboard for the few numbers that matter. Keep it to four.

Fact sheets

A plain <dl> of <dt>/<dd> pairs is a two-column list of facts in small text, ruled like a table. The terms are muted and take only the width they need, up to 42% of the column.

Use it for properties of one thing: the details of a run, a person, a package. Use a table when you compare many things.

Entry lists

A <ul role="list"> or <ol role="list"> is a list of entries: no markers, no indent, a hairline between entries, and more room around an entry than inside it. Entries use the whole column width, and can hold paragraphs, lists and controls.

Use it for things a reader acts on one at a time: messages, findings, tasks. Keep ordinary bulleted lists for points in running text.

Toolbars

A <menu> of <li> items is a wrapping row of controls. A label that wraps a field sits on one line with it, muted, and the field takes only the width it needs, at a smaller size. A text or search field takes whatever room the other controls leave.

Use it for filters above a table or list, and for any row of buttons.

Cards

An <article> is a card: a hairline outline on the white page, a lighter sheet with no outline on the beige paper. In a section it reaches past the text edge by its own padding, so its words stay on the edge; on a phone it runs to both sides of the screen and keeps only its top and bottom rules. A <footer> inside it is a row of small, muted items and buttons.

Use it for the one panel that deserves a spotlight: a top recommendation, a key finding, a few evidence cards. If everything is a card, nothing is. Don't nest cards.

Notes

An <aside> is a note: a tinted block pressed into the page, in smaller text. Headings inside it shrink to the same small size. Like a card, it reaches past the text edge.

Use it for a caveat, a tip or the one thing to remember, set apart from the argument of the page.

Choice cards

Wrap a radio or checkbox and a <span> in a <label>, and the label becomes a large, tappable card. Put the title in <strong> and an optional description in <small>. The chosen card takes an accent outline and a faint accent wash, and the card, not the input, carries the focus ring. Without the <span>, the label stays an ordinary inline control.

Use it when each option needs a line of explanation, or when the choice is the main thing on the page. Stacked cards sit a small gap apart; in a question form they are one question's options.

Segmented controls

Put labels, each wrapping a radio and a <span>, inside an element with role="radiogroup". The radios become segments on one line, and the chosen one takes the accent. Each segment is still a real radio, so the keyboard, grouping, validation and form submission work as usual. A segment whose value is empty means "no choice yet": chosen, it is a plain raised tab, so the accent stays for real answers.

Use it for one choice among two to four short options, such as a decision per row in a list. For a strip of commands rather than a choice, use a button group.

Question forms

Add data-form="questions" to a <form> to lay it out as a questionnaire. Each <fieldset> is one question and its <legend> is the question text. An optional <p> under the legend is a hint.

  • Questions are numbered automatically. On a wide screen the numbers hang in the margin.
  • Questions are set apart by space, and choice cards inside them are spaced for you.
  • An <abbr title="required">*</abbr> in the legend is a required mark in the danger colour. When a question holds an invalid answer after the person has interacted or tried to submit, its number turns red too.
  • A trailing <footer> becomes an action bar that sticks to the bottom of the window. An <output> in it is a small muted status.

The demo above leaves out the footer, because a sticky bar inside this page would cover the docs. See the whole thing, footer and validation included, in the question form demo, or in the longer questions example.

<form data-form="questions">
  <fieldset>…</fieldset>
  <footer>
    <button type="submit">Send answers</button>
    <output>2 of 5 answered</output>
  </footer>
</form>

Use it when you need several answers from someone: a survey, an intake form, a set of decisions.

Switches

Add role="switch" to a checkbox for a sliding toggle. Off, the track is the control-outline colour; on, it takes the accent and the thumb slides across.

Use it for a setting that is on or off and takes effect at once. For an option that is sent with a form, a plain checkbox is clearer.
