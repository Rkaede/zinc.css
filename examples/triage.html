Features worth adding to Pantry

The strongest opportunity is to make the week plan easy to change, shop from and cook from. These 9 proposals build on Pantry’s existing planner and shopping list, each with a starting scope and evidence from the team’s saved research links.

Direction

Make the week plan the one place that drives everything else.

Start by making a plan easy to change, then let it produce a tidy shopping list and a cook mode that works at the bench. Shared plans and cost estimates come once the plan itself is dependable.

  1. Plan the week and move meals freely.
  2. Shop from one merged, ordered list.
  3. Cook one step at a time.
Everything here runs in the existing web app; only shared plans need new server storage.

The five strongest opportunities

  1. Drag recipes between days in the week planner
    Plans change mid-week. Today the only way to move a meal is to clear the slot and search for the recipe again.

  2. Merge matching ingredients on the shopping list
    Duplicate lines are the most common complaint in the saved research, and the ingredient database already has the IDs needed to fix it.

  3. Add a step-by-step cook mode with timers
    Recipes are read at the bench with messy hands. The current recipe page is built for browsing, not cooking.

  4. Suggest recipes from what is already in the pantry
    Wasting less food was the most common reason the saved links gave for planning meals at all.

  5. Scale servings and convert units
    Small, self-contained and requested often. The unit families that F02 relies on make it cheap.

Basis: all 30 links saved to the team’s research board, with articles read in full where the page was still available. This is a feature screen, not a usability study. 3 links were saved as partial captures. Review scope and limits.

    Drag recipes between days in the week planner

    Now · Plan · Effort M · Extend planner · F01

    Move a planned meal to another day without deleting it and adding it again.

    First version. Drag a recipe card onto another day or meal slot, with a keyboard alternative (a Move to… menu). Swapping two meals is one action, and the shopping list updates without a reload.

    Implementation · Web app

    Pointer dragging needs keyboard and touch paths. Announce each move to screen readers.

    Merge matching ingredients on the shopping list

    Now · Shop · Effort M · Extend list · F02

    Show one line for 600 g of onions instead of three lines from three recipes.

    First version. Combine items that share an ingredient and a unit family, with a tap-to-expand breakdown by recipe. Items in incompatible units (two cans and 400 g) stay on separate lines rather than being guessed.

    •
    Why, how it fits, evidence

    Why this priority

    Duplicate lines are the most common complaint in the saved research, and the ingredient database already has the IDs needed to fix it.

    Implementation · Web app

    A pure merge function over list items, keyed by ingredient and unit family, that keeps the source recipes on each merged line.

    Conversion is the risky part. Start with mass and volume, and never convert count units.

    Scale servings and convert units

    Now · Cook · Effort S · Extend recipe · F05

    Cook for six from a recipe written for four, in metric or imperial.

    First version. A servings stepper on the recipe page that scales quantities, rounds to sensible kitchen amounts and offers a metric or imperial toggle. Scaled amounts carry through to the shopping list.

    •
    Why, how it fits, evidence

    Why this priority

    Small, self-contained and requested often. The unit families that F02 relies on make it cheap.

    Implementation · Web app

    Scale at render time from the stored quantity, and never write scaled values back to the recipe.

    The rounding rules matter more than the maths: 1.33 eggs should read as one large egg, with a note.

    Sequence

    Fix the weekly loop, then widen it. Value ranking and build order differ. Start with one complete path from plan to plate, and add shared and server-side features after that path is solid.

    1. Fix the weekly loop

      Move meals, merge the list and scale recipes. Each is contained and improves something people already use every week.

      F01 · Moving meals · F02 · Merged list · F05 · Scaling

    2. Help at the bench

      Add cook mode and pantry suggestions, so the plan is useful after the shop as well as before it.

      F03 · Cook mode · F04 · Pantry suggestions

    3. Bring the household in

      Share a read-only plan and order the list by aisle. Sharing is the first feature that needs the server.

      F06 · Shared plans · F07 · Aisles

    4. Test the bigger bets

      Run small spikes on photo import and cost estimates before committing to either.

      F08 · Photo import · F09 · Cost estimate

    Shared foundations: ingredient IDs on every list line → unit families with base quantities → plan entries with stable IDs. These support merging, scaling and pricing, and later leftovers. Keep the current local storage for plans until sharing needs the server.
